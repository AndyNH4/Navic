# Rezeener 开发标准

本标准适用于 Rezeener / Navic 的功能开发、重构、修复和发布。与 `AGENTS.md` 配套使用：架构约束以 `AGENTS.md` 为准，构建环境以 `BUILDING.md` 为准，功能验收以根目录 `requirements.md` 为准，实际进度以 `DEVELOPMENT_LOG.md` 为准。

“必须”是合入门槛，“建议”是默认做法；偏离时必须记录原因和影响。

## 1. 完成定义（Definition of Done）

一项功能只有同时满足以下条件，才能标记为“已验证”；只有随版本发布后才能标记为“已发布”。

- 需求、边界和异常行为明确，代码覆盖所宣称的场景。
- 数据库变更带正式 Migration、更新版本和 Room schema，并验证升级路径。
- 新文案同时补齐英文、简体中文、繁体中文。
- 相关构建和检查通过，真实调用已验证；不能验证的环境明确列为未验证。
- 开发日志记录结果、验证证据、遗留风险和下一步，PRD 状态同步更新。
- 没有混入无关格式化、用户已有改动、本机配置或生成垃圾文件。

禁止把“代码写完”“编译通过”“真机已验证”“已发布”混称为“完成”。

## 2. 开发状态口径

| 状态 | 使用条件 | 必须记录 |
|---|---|---|
| 未开始 | 只有需求或方案 | 目标、优先级、依赖 |
| 进行中 | 正在设计或编码 | 已完成部分、剩余部分、阻塞 |
| 代码完成，待验证 | 实现结束但场景未全部验收 | 已运行检查、未验证环境、遗留风险 |
| 已验证 | 声明范围内的验收通过 | 命令/操作、结果、设备/服务端环境、代码版本 |
| 已发布 | 已随正式版本发布 | 版本、产物、发布验证 |
| 阻塞 | 依赖缺失或问题使工作无法继续 | 具体原因、已尝试方法、需要的决策或资源 |

状态可因回归后退；发现新问题时应更新状态，不能删除历史验证边界。

## 3. Kotlin 与代码风格

- 使用 Kotlin 和项目现有架构，不引入未经 manifest / lockfile 确认的库。
- 遵循 `.editorconfig`：UTF-8、LF、Tab 缩进、文件末尾换行；新增和修改行尽量不超过 100 列，不为宽度做无关批量重排。
- 文件名、类名、包结构和依赖方向与相邻代码一致。领域逻辑放 domain/repository，数据库访问放 data/database，Compose 只负责展示和交互。
- 优先小函数和共享实现；同一身份、署名或筛选规则不得在多个页面复制出不同版本。
- 默认不写复述代码的注释；只记录非显而易见的协议约束、兼容原因或风险。
- 优先使用显式类型和项目现有 StateFlow 后备字段写法；取消异常必须继续抛出，不能吞成普通错误。
- 不做与本任务无关的“顺手修复”或全文件格式化。

## 4. 艺术家与歌曲元数据标准

- **身份、别名、署名三者分离**：艺术家身份不等于名称，名称不等于歌曲里的整段署名。
- 只使用服务端结构化 `artists` / `albumArtists` / `contributors`、稳定 ID 和 MusicBrainz ID 建立关系。
- 禁止根据 `feat.`、`&`、逗号、斜杠或同名自动拆分/合并身份。手工合并必须可逆。
- 结构化歌曲艺术家为空时显示原始 `artistName`；可信单一 ID 才提供导航。空 ID 和 `unknown artist` 只显示文本。
- 原始字段用于服务端同步、scrobble、歌词匹配和诊断；本地别名只影响展示与导航，不能反向覆盖原始字段。
- 分组成员专辑、歌曲、收藏和下载范围通过共享仓库规则计算；歌曲按 `songId` 去重，艺术家按分组身份去重。
- “艺术家专辑”和“参与歌曲”必须有不同筛选语义；合作歌曲可出现在多个艺术家详情，但全局统计不得因此重复放大总数。
- 多语言别名必须使用显式语言/文字标签和稳定回退顺序，不把字符集猜测描述成完整语言识别。

## 5. 数据库与本地数据

- 加表、改表、索引或字段语义变化时，必须同步完成：实体/DAO、`@Database.version`、正式 Migration、`addMigrations(...)` 和导出的 schema JSON。
- `fallbackToDestructiveMigration(true)` 只是最后保护，不得用它代替升级迁移；用户手工整理、下载和设置不得因升级静默丢失。
- Migration 必须能从支持的旧版本逐级升级，不能只在全新安装上验证。
- 多步分组、合并和关系写入应保持事务一致性；避免读到只完成一半的更新。
- 服务端同步不得覆盖本地手工别名、主身份或固定显示名；缓存清理与登出策略必须区分可重建缓存和用户数据。

## 6. API、同步与离线

- API 调用在使用时通过 `sessionManager.api` 获取，禁止长期持有主 URL 对应的 client。
- 先定义协议缺失、旧服务端、空列表、超时和部分失败行为，再写成功路径。
- 收藏、评分等离线动作使用现有 SyncAction 队列；分组成员需要逐个入队，不能只操作主 ID 后显示整个分组成功。
- 可恢复错误保留本地数据并提供反馈；不能因单个成员失败静默丢弃其他成员的操作状态。
- 离线浏览、搜索和导航不得触发逐行网络请求；恢复在线后不得重复计数或重复导入事件。

## 7. UI、交互与本地化

- 复用 `SongRow`、`ArtGrid`、`CoverArt`、公共 Sheet 和既有 defaults，不复制仅样式不同的组件。
- 手机与宽屏都要验证；网格列数服从现有偏好，媒体行填充可用宽度，不使用无理由固定尺寸。
- 同一艺术家/歌曲在列表、详情、Sheet 和播放页的点击、收藏、下载及导航行为应一致。
- 多艺术家名字分别链接到真实身份；无身份时不能呈现看似可点击的伪链接。
- 新文案进入 `values/strings.xml`、`values-zh-rCN/strings.xml`、`values-zh-rTW/strings.xml`；图标补充合适的 content description。
- 至少验证一种 Material 主题和一种非 Material 主题、长名称/长列表、返回导航及偏好重启持久化。

## 8. 性能标准

- 万级曲目是基线验收规模；新增查询需说明复杂度和内存中集合规模。
- 禁止逐歌曲/逐行网络请求；批量读取优先于循环 DAO 查询，无法避免时在开发日志记录原因。
- 列表项组合中不得执行阻塞数据库或网络调用； expensive work 放在 ViewModel / repository 的合适调度器。
- 搜索、分组和统计必须限制结果、稳定排序并正确去重；不能只看小样本正确性。
- 性能结论必须来自测量，记录曲库规模、设备、耗时或卡顿现象；未测量时写“未验收”。

## 9. 验证标准

### 每次代码改动

```bash
./gradlew :app:assembleDebug
```

可在开发中运行 `./gradlew :app:compileDebugKotlin` 做快速检查，但它不能替代最终 APK 构建。不得并发运行多个 Gradle 构建。

当前项目没有 `app/src/test` / `androidTest` 测试，不得声称存在或通过了单元/UI 自动化测试。未来引入测试体系后，优先覆盖解析、别名匹配、分组筛选和数据库迁移。

### 发布前

- 顺序执行 `:app:assembleDebug` 和 `:app:assembleRelease`。
- 验证 APK 的 applicationId、版本和签名；按 `AGENTS.md` 的标签 CI、草稿 Release 流程发布。
- 记录实际验证的设备和服务器版本；没有设备时明确保留真机场景，不能用编译通过替代。

### 艺术家元数据最低手工验收矩阵

| 场景 | 预期 |
|---|---|
| `artists=[A,B]` | A、B 分别显示和导航，顺序保持，无合成身份 |
| 只有 `artistName="A feat. B"` | 原文完整显示，不猜拆 B，不出现空白 |
| 空 ID / `unknown artist` | 显示名称或兜底文本，但不导航到错误详情 |
| 分组“艺术家专辑”查看全部 | 包含所有成员专辑歌曲并按 songId 去重 |
| 分组“参与歌曲”查看全部 | 包含成员参与歌曲，排除已归属成员专辑的歌曲 |
| 收藏/取消收藏分组 | 所有成员本地状态一致，每个 ID 都有同步动作 |
| 离线操作后恢复 | 队列继续同步，无重复、无静默丢失 |
| 手机与宽屏、长名称 | 链接、布局和返回行为正常 |

## 10. Git、文档与交付边界

- 按功能拆分英文 Conventional Commits；提交前审阅 diff 和 `git status`，不得混入用户已有修改。
- `gradle/wrapper/gradle-wrapper.properties` 的本机镜像补丁不提交；`androidx-media/` 不作为普通业务源码修改。
- 密钥库、凭证、日志和本地构建输出不得进入提交；构建后检查新生成文件。
- 未经明确要求不自动 push、打标签或发布。
- 每个功能结束更新 `DEVELOPMENT_LOG.md`：范围、状态、实现、验证证据、未验证项、遗留风险、下一步；同步更新相关 PRD 和 `AGENTS.md` 状态。

## 11. 开发状态记录模板

```text
功能：
状态：未开始 / 进行中 / 代码完成，待验证 / 已验证 / 已发布 / 阻塞
范围：
实现结果：
验证命令与结果：
验证环境：
未验证项：
遗留风险：
下一步：
```

记录必须对应实际代码和证据；后续修改旧结论时追加或更新状态，不保留与代码相反的说明。
